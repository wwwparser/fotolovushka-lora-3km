LoRa point-to-point, один радиоканал; не LoRaWAN и не Meshtastic. Общие параметры двух радио: 868950000 Гц как предварительный сценарий РФ, BW125 кГц, SF7, CR4/5, preamble8, explicit header, PHY CRC, sync word0x12, conducted TX10dBm. Передача по умолчанию отключена ENABLE_RF_TX=0; частота, мощность и duty проверяются для региона перед включением. SX1262 этим драйвером не поддерживается.

Все многобайтовые поля little-endian. Заголовок 26 байт, структура Python <2sBBHIHHIII, packed C++.

Поле Размер, байт Значение
magic 2 ASCII FT
version 1 1
kind 1 1 DATA, 2 ACK
node 2 1–4
image 4 Случайный uint32; уникальность вероятностная
index 2 Фрагмент 0…total−1
total 2 ceil(size/200)
captured 4 UTC unix seconds, 0 если часы не установлены
size 4 Размер JPEG, 1…32768
crc 4 IEEE CRC32 всего JPEG
payload до 200 DATA; в ACK отсутствует

DATA передаётся по одному фрагменту с stop-and-wait. ACK повторяет все поля DATA, kind=2. Узел сверяет весь заголовок. Пять попыток, 15 с окно ACK, случайная дополнительная пауза при потере. Между передачами выдерживается расчётное off-time (ToA/duty)-ToA; для узла ожидание в light sleep. После последнего кадра off-time выдерживается до deep sleep, чтобы немедленное PIR-пробуждение не обошло ограничение. Пауза после старта дополнительно ограничивает перезапуски. Это простой ограничитель по каждому пакету, не сертифицированный измеритель duty/LBT.

USB базы: строка D:<hex packet>\n от шлюза. Python проверяет поля/размер, сохраняет фрагмент в SQLite, завершённый JPEG проверяет по CRC и SOI/EOI, затем отвечает A:<hex ACK>\n. До сохранения подтверждение не отправляется. Повтор уже завершённого кадра получает ACK и не создаёт повторное задание почты. Фрагменты переживают перезапуск приёмника; незавершённые старше суток очищаются, одновременно максимум 16 незавершённых кадров. Завершённые ID сохраняются; эксплуатационная политика удаления истории/фото ещё нужна.

Изображение, JSON времени и запись очереди почты появляются после сборки. SMTP идёт отдельным потоком и не блокирует ACK. Письмо отправляется с вложением JPEG; при ошибке повторяется не чаще раза в минуту. SMTP delivery имеет семантику at-least-once: если сервер принял письмо, а процесс умер до отметки sent, возможен повтор. Message-ID стабилен, но не гарантирует дедупликацию почтовиком. Используются TLS/465 и пароль приложения из .env.

Без RTC время помечено base_first_fragment_estimate, а не выдаётся за точное время PIR. DS3231 должен хранить UTC; настройка отдельной прошивкой rtc_set, Unix UTC берётся с ПК. Задержка от движения до экспозиции включает старт камеры и AEC (порядка секунд, измерить). CRC защищает от случайной порчи, шифрования/аутентификации нет. Для охранного применения нужны AEAD и управление ключами.

Приёмник умеет четыре node ID, но радио-MVP испытать сначала с одним узлом. Четыре одновременных отправителя не имеют TDMA/центрального планировщика, устойчивость к коллизиям не доказана. Во время передачи узел пропускает новые события PIR и не имеет SD-очереди. При превышении лимита попыток кадр в RAM теряется; сохранение локальной очереди — следующая версия.
